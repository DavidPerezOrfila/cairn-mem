# Design (v2, after review)

## Goal

Persistent memory for coding agents that is **effective, cheap in latency and cost, and
portable to any harness with a shell**.

## Principles

1. **CLI plus files.** MCP (v0.2) is a second front end over the same `Store`. Hooks stay
   out of scope.
2. **No LLM and no embeddings.** FTS5 with BM25 is enough until a measurement says
   otherwise.
3. **Short, typed memory:** `decision | convention | gotcha | fact`, body ≤ 500
   characters, with a `why`.
4. **One source of truth:** `events.jsonl`. The database and `MEMORY.md` are derived and
   can be rebuilt.
5. **Environment-derived state is not persisted.** "Stale" is calculated when reading.
6. **Simple before complete.** Every extra piece needs a measurement that justifies it
   (see the backlog).

## Layout

```
.cairn/
  events.jsonl    # TRUTH. Append-only. UTF-8 without BOM.
  sessions.jsonl  # session recaps (append-only, local)
  cairn.db        # derived (gitignored)
  MEMORY.md       # derived L0 (gitignored), generated by `cairn render`
  .gitignore      # created by `cairn init`
```

- `cairn init` is local-only by default, and it also ignores `events.jsonl`.
  `cairn init --share` versions `events.jsonl`.
- Project root: cairn searches for `.cairn/` upward from the cwd (like git) or uses
  `CAIRN_DIR`. It excludes `~/.cairn` and `CAIRN_HOME` from that search, because those
  are the personal scope.
- Personal scope: `CAIRN_HOME` or `~/.cairn`, with the same layout. Its `MEMORY.md` does
  not mix with the project L0.

## Events (only 2 operations)

```json
{"op":"save","id":"a1b2c3d4e5f6","ts":1788000000000000000,"kind":"gotcha","topic_key":"auth/redirect","title":"...","body":"...","why":"...","anchor_path":"src/auth.py","anchor_hash":"..."}
{"op":"archive","id":"a1b2c3d4e5f6","ts":1788000000000000001}
```

- `save` with an existing `id` updates the memory; the last one wins.
- `save` with an active `topic_key` marks the previous one as `superseded`, and that
  happens before the insert.
- Write: **one `os.write` call with `O_APPEND`**, line < 4 KB. No file lock (one writer
  per project is the normal case; light concurrency is tested).
- Before each append, cairn repairs the tail. If the file does not end in `\n` (a crash
  in the middle of a write), a valid JSON fragment keeps its line and gets the newline;
  an invalid fragment is truncated. That way the next event never lands on a broken line.
- JSON with `ensure_ascii=False`. Files are always opened with `encoding="utf-8"`
  (Windows).

## Database and JSONL sync

When the `Store` opens, it compares `(size, mtime_ns)` of the JSONL with `meta`. A
long-lived `Store` does the same on every read and write. If the file only grew and the
applied prefix (`jsonl_offset` plus its sha1) is unchanged, it applies just the new suffix
(`_catch_up`). Otherwise (for example after a `git pull`, a truncation, a same-size replace,
an `archive` or an update of an existing id) it runs a full `rebuild()` in file order (the
order events were appended, which is the order `_catch_up` already uses) and then
`render()`. Ordering the rebuild by `ts` re-derived a different winner for a topic whenever
an `archive` fell between two `save`s: the memory the CLI had just stored came back
`superseded` and a fresh clone saw no active memory for that topic. `ts` still decides who
wins a topic, but through `_apply`'s "a newer active row exists" check, not through the
order of the replay. Own writes update the fingerprint in the same
transaction and compare the fingerprint **before the append**, including `mtime`, not just
the size, so an external replacement that keeps the size is still detected. A different
`PRAGMA user_version` drops the derived schema (`mem`, `mem_fts`, `meta`) and rebuilds it.
Expected full rebuild cost with 10k events: seconds on a busy machine (measured 3.3 s on
2026-11-09; 570 ms when idle in S2). Incremental catch-up stays in the low milliseconds;
see `docs/features/s7-incremental-sync.md`.

## Writing and security

- **Reject** (do not redact) text that looks like a secret: cloud keys (`AKIA...`),
  `-----BEGIN ... PRIVATE KEY-----`, JWTs (`eyJ...`), provider tokens (`ghp_`,
  `github_pat_`, `glpat-`, `sk-proj-`, `sk-ant-`, `AIza...`), `password|secret|token|api_key
  = value`, and URLs with `://user:pass@`. The message is clear: "rewrite it without the
  secret".
- A `body` over 500 characters is an error, and the message asks you to split it into two
  memories.
- `id` must be 12 lowercase hex characters. `topic_key` is at most 100 characters and
  cannot contain control characters, because a newline would inject lines into the L0.
  `render` also collapses id, title and topic when reading, to cover external events
  written before this validation existed.
- Scrubbing happens since M1, **before** anything reaches the JSONL.

## Sessions (M6)

- Session recaps live in `.cairn/sessions.jsonl`, append-only and local (gitignored).
- Event: `{"op":"session","id":"...","ts":...,"summary":"..."}`. No 500-character limit.
- They do not go into `events.jsonl`, FTS or the L0. They are continuity, not curated
  memory.
- Read: replay in memory (there are few), tolerating a torn last line.
- `context` reads only the tail: a window of `MAX_SUMMARY * 6 + 1 KB` bytes (a valid recap
  can take 6 bytes per character once JSON escapes it) that widens until the newest record
  fits. A fixed 64 KB window looked big enough for 20,000 characters, but 20,000 emojis are
  80 KB, and the tool then answered with the recap before the last one.
- Commands: `cairn session save|list|get` (with `--personal` for the personal scope).
  MCP exposes `save_session` (write), `session_list` and `session_get` (read). The `context`
  tool returns the L0 and then the last **project** recap (at most 4,000 characters), so
  a new session starts knowing where the previous one stopped. A personal recap from
  another repo does not mix in. `cairn context` prints the same text from a shell.
- `Sessions.save` goes through the same `reject_secrets` as `Store.save`.

## Personal scope (M7)

- Directory: `CAIRN_HOME` or `~/.cairn`. `CAIRN_DIR` still wins for the project.
- `save --personal` uses that `Store`. `get` looks in the project first and then in the
  personal scope.
- `search` is **cross-scope**: it queries both stores and interleaves results by ranking
  position (BM25 scores from different databases are not comparable), starting with the
  project. Each result carries `scope`; in text, personal results are marked `[personal]`.
  `--personal` or `scope=personal` restricts the search to the personal scope. If there
  is no project `.cairn/` but there is a personal scope, the search returns personal
  results only.
- MCP: `scope` in `save` (`project|personal`) and in `search` (`project|personal|all`,
  default `all`).
- The L0 is always the project L0. Personal memory does not mix into it.

## Legacy importer (M8)

- `cairn import legacy --db PATH [--dry-run]` reads a foreign SQLite database in read-only
  mode.
- `type` becomes `kind`: decision/architecture/config → decision; pattern → convention;
  discovery/bugfix → gotcha; everything else → fact. `session_summary` →
  `sessions.jsonl`.
- Content: `What` → `body` (at most 500 characters), `Why/Where/Learned` → `why`.
- `project` rows go to the `.cairn/` of the repo marked by `capture_project_provenance`.
  `global/personal` rows go to the personal scope. Deleted and superseded rows are
  skipped.
- The id is deterministic, derived from the source id and a fixed salt, so importing again
  does not duplicate anything.

## Reading

| Level | What | Size |
|---|---|---|
| L0 | `.cairn/MEMORY.md`: `- [id] kind: [topic] title, 120 chars of body` | **≤ 3000 characters** (about 900 tokens) |
| L1 | `cairn search`: `id, kind, topic_key, title, snippet, stale, scope` | about 50 tokens per result |
| L2 | `cairn get <id>`: full record | ≤ 500 chars of body |

- **L0** is regenerated after every `save/archive` and after a rebuild. The order is
  deterministic: round-robin by `kind` (each round goes convention > decision > gotcha >
  fact), newest `ts` first inside each kind, until the budget is full. That way a kind
  with many entries cannot push the others out. `[topic]` only appears when the memory has
  one.
- **Search:** stopwords dropped and the plural trimmed before FTS5 (`\w+` → `"t"*`,
  prefix); the stem keeps at least 5 characters (`redis` must not become `redi`).
  **AND first and OR if there are no results**, with no quorum: requiring two roots cut
  paraphrase Hit@3 from 0.90 to 0.40 (S6.1). Ranking is
  `bm25(mem_fts, 5.0, 1.0, 0.5, 3.0, 2.0)` over
  `title, body, why, topic_key, anchor_path` (title > topic > anchor > body > why), and a
  `status='active'` filter. No other boosts in v0.1.
- Raw FTS5 queries **fail** with `-`, `:` and `"` (for example `oauth-callback`), so
  sanitizing is required.

## Anchors and stale (calculated, not stored)

- `anchor_hash` is the sha1 of the file with `\r\n` → `\n`, which avoids false stale flags
  between Windows and Linux.
- `anchor_path` is a POSIX path relative to the root.
- In `search` and `render`, only for returned results: if the file is missing or the hash
  differs, `stale=true` and the entry shows `⚠ revisar`. It is never hidden or deleted.
- `cairn check` lists every stale memory. Re-anchoring means running `cairn save` with the
  same `--id` and the current `--anchor`: the whole memory is rewritten, so the text gets
  reviewed instead of the flag being cleared silently.

## MCP (v0.2)

- Transport: **stdio with NDJSON** (JSON-RPC 2.0), pure standard library. No SDK, no port,
  no Go.
- `cairn mcp` serves 8 tools: `save`, `search`, `get`, `context`, `save_session`,
  `archive`, `session_list`, `session_get`. Maintenance work stays in the CLI so its
  schemas do not cost tokens on every model turn. `context` injects at most about 7,000
  characters: L0 (≤ 3,000) plus the last recap (≤ 4,000).
- The session tool is called `save_session` because `session` collides with harness name
  spaces, and OpenCode did not expose it.
- The process caches a single `Store`. While it lives, it is the only writer, so it does
  not pay Python startup per call (search p95 4 ms against 304 ms for the CLI). Every
  read compares the JSONL fingerprint and reapplies it if it changed outside (a
  `git pull`, the `cairn` CLI).
- stdout carries protocol only. Diagnostics go to stderr. Reads are blocking, and the
  process exits cleanly when the pipe closes (no signals, portable to Windows, macOS and
  Linux).
- Tool errors return `isError: true` with text. Protocol errors return JSON-RPC errors.

## Commands

`init · save · search · get · context · archive · check · render · rebuild · session · import · mcp`

`context` is the same text the MCP tool of that name returns (L0 plus the last project
recap). A harness with only a shell has no other way to load the recap from the previous
session: `session list` shows an 80-character preview and `render` never includes it.
